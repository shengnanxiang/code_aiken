# AiKen 概念测试页 · 研究执行说明

> 配套文件：
> - `aiken-test-A-完整叙事版.html` —— A 版：完整落地页（四段卖点按 机械爽感 → 成卷纪念 → 直出质感 → 社交货币 排布）
> - `aiken-test-B-单变量对比版.html` —— B 版：五个变体（mech/roll/film/social/ctrl）由 URL 参数切换

---

## 一、设计逻辑

### 文案来源（全部可溯源）
- **机械爽感（Job 3）**：「像网吧键盘的轴体手感」「解压神器」——08-06 晚、08-05 访谈原话
- **成卷纪念（Job 1）**：「一卷对应一段特定时光」「开盲盒式未知感」——08-06 午场原话
- **直出质感（Job 4）**：「满足对胶片的好奇，不承担胶片的成本」——08-06 晚原话
- **社交货币（Job 5）**：「日期水印带来炫耀感」「拼贴分享是必选项」——08-12 午后、08-06 午场原话
- **数据**：36 张/40 秒/9 种风格/0 耗材——功能说明书与 KANO 文档

### A 版 vs B 版的分工
| | A 版 | B 版 |
|---|---|---|
| 回答的问题 | 整条叙事链是否成立、用户在哪段流失 | 四个卖点单打独斗时哪个转化力最强 |
| 形态 | 完整落地页，7 段结构 | 单卖点短页 × 4 + 对照组 × 1 |
| 数据 | 段落停留时长、滚动深度、CTA 点击位置 | 停留/滚动/CTA **按变体分组对比** |
| 用法 | 投流或定向分发，看自然行为 | 5 个链接分 5 组人，每组 n≥30 |

### 对照组（ctrl）的意义
B 版第 5 个变体是**中性参数页**（无情感叙事，只有规格表）。任何 Job 页与对照组的差值，就是"Job 叙事本身的增量"——没有对照组，你无法区分"用户被机械爽感吸引"和"用户看到任何相机页都会点预约"。

## 二、怎么发链接

```
A 版：aiken-test-A-完整叙事版.html（直接发）
B 版：aiken-test-B-单变量对比版.html?job=mech   ← 机械爽感组
     aiken-test-B-单变量对比版.html?job=roll   ← 成卷纪念组
     aiken-test-B-单变量对比版.html?job=film   ← 直出质感组
     aiken-test-B-单变量对比版.html?job=social ← 社交货币组
     aiken-test-B-单变量对比版.html?job=ctrl   ← 对照组
```

- 双击 HTML 文件即可在浏览器本地运行，无需服务器
- 分发建议：小红书/微信群定向投放或招募，**一个用户只发一个链接**（避免交叉污染）；正式投流时把 alert 换成真实预约表单跳转
- 变体分配要随机或轮流，不要"先发 mech 链接给最积极的人"造成分样偏差

## 三、怎么读数据

### 数据采集（内置）
两个页面都内置了轻量埋点：
- 停留时长（自动扣除页面切走的时间）
- 最大滚动深度
- 各段落累计可视时长（1 秒采样）
- CTA 点击记录（时间点、当时滚动位置、所在段落）

### 取数方法
被试看完页面后（或在测试机上），打开浏览器控制台（F12 → Console），执行：
```
aikenTest.export()   ← 当前会话数据（实时）
aikenTest.raw()      ← 本机全部历史记录（含 localStorage 存档）
```
`beforeunload` 时自动存入 localStorage，同一台设备多人测试可以最后统一取 `raw()`。

### 判读标准（预设，避免事后找理由）

**A 版判读：**
| 指标 | 强信号 | 弱信号 |
|---|---|---|
| 机械段停留 / 全页停留 | ≥ 30% | < 15%（叙事链断裂，Hero 主叙事需重估） |
| 成卷段完成率（滚过该段） | ≥ 60% | < 40% |
| CTA 点击位置分布 | 若 50%+ 点击发生在前两段 → 验证「机械爽感 > 成卷纪念」排序 | 若集中在底部 CTA → 需要看段间流失 |
| 首屏跳出（<10 秒离开） | < 30% | > 50%（Hero 表达失败） |

**B 版判读（组间对比，n≥30/组）：**
| 指标 | 说明 |
|---|---|
| CTA 点击率 | 主指标。mech vs roll vs film vs social 各组对比，ctrl 是基线 |
| 停留时长 | 辅助指标（叙事吸引力） |
| 滚动深度 | 辅助指标（信息是否被消费） |
| 胜出判定 | 某变体 CTA 率超出 ctrl 基线 1.5 倍以上且样本量足够，视为该 Job 有独立转化力 |

### 与 JTBD 文档的回写
B 版胜出的 Job，应回写到 `AiKen_JTBD重解码_内部样本版.md` 对应 Job 的「外部验证」栏——形成「假设 → 测试 → 修正」的闭环。若机械爽感（mech）胜出，印证内部访谈排序；若 social 胜出，说明内部样本低估了社交货币（内部人视角往往低估"炫耀感"这类社交动机的真实权重——他们不好意思承认）。

## 四、已知限制（诚实声明）

1. **本测试是"卖点吸引力"测试，不是"购买意愿"测试**——CTA 是预约不是付款，数字会系统性偏高，用于**组间相对比较**是可靠的，绝对值不可外推
2. **结构占位图会压低整体表现**——样张位是虚线框，直出质感（film）组受影响最大，读数时注意：film 组的绝对值低估，若它仍能胜出，信号极强
3. **无真实样张和收音视频**——机械爽感（mech）组的说服力打了折扣（手感无法隔着屏幕传达），mech 组胜出要求更保守判定
4. alert 弹窗会打断体验——正式投流前务必替换为真实表单/跳转
5. localStorage 方案适合小规模定向测试；正式投流请接埋点系统（对应你们埋点文档的 events 体系）

## 五、接入正式系统时的替换清单

| 位置 | 现状 | 替换为 |
|---|---|---|
| 所有 `data-cta` 按钮的 alert | 测试提示 | 预约表单跳转 / 埋点上报 |
| Hero 产品图占位 | 虚线框 | 45° 产品图 / 抽拉动作特写（真收音） |
| film 组风格色卡 | CSS 渐变 | 固件真实直出样张 |
| 日期戳/拼贴展示位 | 无图 | App 真实截图 |
| localStorage | 本地存档 | 埋点系统 + 渠道参数（utm） |
