# AiKen 用户使用数据采集方案

> 版本：v1.0 ｜ 状态：待评审 ｜ 适用范围：AiKen 数码相机硬件端 + 米家插件（App 端）

---

## 一、方案背景与产品理解

### 1.1 产品定位

AiKen 是一台"复刻胶卷体验的潮玩数码相机"：

- **形态**：110 胶卷相机复古造型，无屏幕、泛焦、拿起就拍，仅保留 LED 显示剩余张数；
- **体验**：以"过片、36 张一卷、取出后冲扫"复刻胶卷的仪式感与等待感；
- **核心价值**：潮流外观 + 氛围感直出（胶片风格滤镜）+ 慢节奏玩法，面向热爱氛围感的年轻潮人（18–30 岁）。

### 1.2 硬件与软件构成

| 端 | 构成 | 关键信息 |
|---|---|---|
| 硬件 | AiKen 相机本体 | 开关闸（开闸=开机+过片，关闸=关机）、快门/印放/复位三键、128MB 存储（约 36 张/卷）、蓝牙 + Wi-Fi |
| 软件 | 米家插件（App 端） | 相机页、风格、冲扫、暗房、创作、设置、打印机联动七大模块 |
| 联动 | 口袋照片打印机 | 蓝牙配对后支持"印放最后一张"，形成"拍-选-印"的线下闭环 |

### 1.3 核心用户旅程（主循环）

```
开闸开机 → 过片 → 拍摄（36 张/卷）→ 关闸/接取 → App 选择风格
        → 取出/传输 → 冲扫（即时 / 经典 3–24h 随机）→ 暗房查看
        → 保存成片 → 开启下一卷
        （可选延伸：分享到社交平台 / 口袋打印机印放，非必需路径）
```

产品成败的关键在于：**用户能否走通"拍摄→取卷→冲扫→回看→保存"的完整循环并持续开卷拍摄**。分享是期望发生的增值行为，不构成必需路径（不分享不影响正常使用）；AiKen 为模拟胶卷体验的数码相机，不存在实体胶卷耗材，因此无"复购卷数"概念，用户价值在于持续产出并回看自己的"胶片"照片。数据采集方案围绕这一主循环设计。

## 二、方案目标

### 2.1 总体目标

建立一套覆盖"硬件使用 + App 行为 + 业务结果"的全链路用户数据采集体系，支撑产品迭代、运营策略与商业决策。

### 2.2 北极星指标（建议）

> **每台活跃设备每周完成的"取卷-冲扫"次数（周冲扫卷数）**

理由：该指标同时反映硬件使用（拍满并取出）与 App 使用（完成冲扫回看），是用户真正进入产品循环的标志，且与"复刻胶卷体验"的核心价值强相关。

### 2.3 具体目标分解

1. **理解核心循环**：还原用户从"开机拍摄"到"保存成片"的全路径，找出流失环节（如拍了不取、取了不冲、冲了不看）；分享作为可选延伸行为单独跟踪。
2. **驱动版本迭代**：为风格、冲扫、创作、暗房等模块的功能取舍与体验优化提供量化依据。
3. **支持运营策略**：为风格解锁任务、兑换码活动、口袋打印机联动等运营手段评估效果。
4. **硬件质量监控**：监测拍摄异常、传输失败、电量/存储异常等硬件问题，反哺固件改进。
5. **沉淀用户画像**：基于使用行为构建"轻度/中度/重度用户"分群，支撑精细化运营。
6. **验证商业假设**：验证"胶卷体验"玩法对用户留存与传播的拉动，评估分享/传播的实际价值。

## 三、需要采集的数据

数据按"设备数据 / App 行为数据 / 业务与用户数据"三层组织，全部遵循"最小必要、按需采集"原则。

### 3.1 设备数据（硬件端）

| 数据类别 | 字段/事件 | 说明 |
|---|---|---|
| 设备信息 | 设备型号、固件版本、硬件版本、序列号 | 绑定与版本分布 |
| 激活绑定 | 首次开机时间、首次配对/绑定时间、绑定渠道 | 激活漏斗 |
| 使用状态 | 开机/关机时间、当日开机次数、当日过片次数 | 使用频次 |
| 拍摄行为 | 快门触发次数（含单张/连拍）、每卷张数、弃卷次数 | 核心硬件行为 |
| 卷状态 | 卷创建时间、拍满时间、取出时间、复位时间 | 一卷生命周期 |
| 设备状态 | 电量（充放电曲线）、存储占用、剩余张数、Wi-Fi/蓝牙连接质量 | 状态监控与告警 |
| 异常事件 | 传输失败、连接断开、快门无响应、存储错误、固件升级结果 | 质量监控 |

> 注：硬件数据在 App 连接时随会话上报，或由设备端缓存后批量上报，避免频繁连接消耗电量。

### 3.2 App 行为数据（插件端）

覆盖七大模块：

| 模块 | 关键行为事件 |
|---|---|
| 启动/会话 | 插件启动、页面进入/退出、前台/后台切换、崩溃 |
| 相机页 | 页面曝光、连接/断开、电量查看、风格切换、取出入口曝光与点击 |
| 风格 | 风格列表曝光、风格详情查看、风格选择/切换、收藏 |
| 取出/传输 | 点击取出、传输开始/进度/成功/失败/中断、传输耗时 |
| 冲扫 | 选择冲扫模式（即时/经典）、冲扫排队、冲扫完成、预览、删除 |
| 暗房 | 胶卷列表曝光、胶卷进入、胶卷重命名、单卷删除、照片筛选 |
| 照片浏览 | 单图进入、照片操作（保存/批量保存/删除/设封面/设为头像） |
| 创作 | 创作入口进入、模板选择（朋友圈 9 宫格/小红书竖图）、生成拼贴、重新生成、保存 |
| 分享 | 分享入口点击、分享渠道、分享结果、分享落地页回流 |
| 设置 | 冲扫方式设置、可用风格管理、日期戳开关、自动保存开关、绑定管理 |
| 打印机联动 | 打印机配对、连接、印放请求、印放成功/失败、印放耗材状态 |

### 3.3 业务与用户数据

| 数据类别 | 内容 |
|---|---|
| 用户身份 | 设备绑定的米家账号 ID、绑定时间、解绑时间 |
| 风格解锁 | 解锁方式（任务完成/兑换码/默认）、解锁时间、兑换码来源 |
| 活动数据 | 活动曝光、参与、完成（如解锁任务进度） |
| 内容沉淀 | 保存到相册/云端的照片数、分享传播带来的回流 UV/PV |
| 硬件-账号关系 | 一机多账号、一账号多机（多设备管理） |

### 3.4 数据采集合规要点

- 仅采集产品功能所需数据，照片内容默认不上传（冲扫仅取元数据与缩略图）；若需云端优化需单独授权；
- 位置信息、相册读取等敏感权限按需申请并明确告知；
- 遵守《个人信息保护法》及米家开放平台数据规范，提供隐私协议与数据删除入口。

## 四、数据分析方法

### 4.1 分析方法矩阵

| 分析方法 | 用途 | 适用场景 |
|---|---|---|
| **漏斗分析** | 定位核心链路流失 | 激活漏斗、拍摄→取出→冲扫→查看→保存漏斗、传输漏斗；分享作为独立延伸漏斗单独分析 |
| **留存分析** | 衡量产品粘性 | 次日/7 日/30 日设备活跃留存；按"是否完成首次冲扫"分组对比 |
| **分群分析（Cohort）** | 对比不同群体行为差异 | 按激活渠道、首卷完成时间、风格偏好、冲扫模式分群 |
| **行为路径分析** | 还原真实使用路径 | 新用户首周行为路径、未完成循环用户的卡点 |
| **频次分布分析** | 识别使用强度分层 | 周拍摄张数、周取卷数、周冲扫数的分布（重度/中度/轻度） |
| **功能健康度分析** | 评估单模块价值 | 各功能使用率、次周留存贡献、对北极星指标的带动 |
| **A/B 测试** | 验证改动效果 | 冲扫时长策略、风格解锁任务难度、创作模板排序 |
| **生命周期价值分析** | 衡量商业价值 | 累计取卷/冲扫次数、耗材（打印机）相关消费潜力 |
| **异常/质量分析** | 硬件可靠性 | 传输失败率、连接断开率、固件升级失败率、崩溃率 |

### 4.2 关键分析框架

**（1）核心循环漏斗**：开机拍摄 → 拍满取卷 → 传输完成 → 冲扫完成 → 查看照片 → 保存，逐层计算转化率，识别最大流失点；分享率作为独立延伸指标观察，不计入循环完成判定。

**（2）"首次冲扫"时刻**：将用户生命周期分为"未完成首冲"与"完成首冲"两个阶段，验证"首次完整体验"对留存的决定性影响。

**（3）风格-冲扫联动分析**：交叉分析"用户使用风格类型 × 冲扫方式（即时/经典）"，评估"氛围感"玩法的实际接受度。

**（4）分享传播分析**：统计分享率、分享渠道占比、回流 UV/PV，评估社交裂变对激活新设备的贡献。

## 五、数据结果（输出指标体系）

### 5.1 核心指标（一级指标）

| 指标 | 定义 | 说明 |

| 激活设备数 | 成功绑定 App 的设备数 | 业务规模 |

| 暗房/浏览 | 卷内照片查看率、单图保存率、批量操作使用率、平均查看照片数/卷 |
| 创作 | 创作功能使用率、模板使用分布、生成-保存转化率、重新生成率 |
| 分享 | 分享按钮点击率、各渠道分享占比、分享回流 UV/PV、分享后保存/关注转化 |
| 打印机联动 | 打印机配对率、印放成功率、印放请求频次、印放-设备购买转化 |
| 设置 | 设置项触达率（日期戳/自动保存）、功能开关开启率 |
| 质量 | 崩溃率、连接断开率、传输失败率、固件升级成功率、电量异常率 |

### 5.3 指标看板（建议分层）

- **管理层看板（周/月）**：激活、WAU、周冲扫卷数、次周留存、分享率等大盘指标；
- **产品层看板（日/周）**：各模块漏斗与功能健康度、异常质量指标；
- **运营层看板（活动期实时）**：风格解锁、兑换码、分享活动实时数据。

## 六、App 端埋点方案

### 6.1 埋点设计原则

1. **事件驱动、端到端唯一 ID**：以 `设备序列号` + `卷 ID` + `照片 ID` 串联硬件→App 全链路；
2. **统一命名规范**：`模块_动作_对象`，如 `style_select`、`transfer_start`、`develop_finish`；
3. **公共参数兜底**：每个事件携带设备信息、固件版本、App 版本、时间戳、会话 ID；
4. **关键节点双向埋点**：涉及设备的状态（如传输）需同时记录"请求方"与"设备回执"，用于对账；
5. **前台补传**：App 离线缓存事件，回到前台/连接网络时批量补传，保证数据完整性；
6. **性能优先**：埋点不阻塞主流程，网络失败不重试阻塞，使用异步上报。

### 6.2 事件命名规范

```
格式：[模块]_[动作]_[对象]
动作枚举：view(曝光) / click(点击) / start(开始) / success(成功) / fail(失败) / cancel(取消) / finish(完成)
示例：camera_view、style_click、transfer_success、develop_finish、print_success
```

### 6.3 公共参数（所有事件必带）

| 参数 | 类型 | 说明 |
|---|---|---|
| `device_sn` | string | 设备序列号（唯一标识硬件） |
| `fw_version` | string | 固件版本 |
| `app_version` | string | 插件/App 版本 |
| `session_id` | string | 本次会话 ID |
| `ts` | long | 事件时间戳（毫秒） |
| `user_id` | string | 米家账号 ID（脱敏） |
| `network_type` | string | wifi / bluetooth / none |
| `entry` | string | 进入插件来源（首页/卡片/通知/分享回流） |

### 6.5 关键漏斗埋点串联

将上述事件组合成可监控的核心漏斗（每个节点给出转化率）：

```
device_connect(连接) 
  → camera_view(相机页) 
  → eject_confirm(取出确认) 
  → transfer_success(传输成功) 
  → develop_start(开始冲扫) 
  → develop_finish(冲扫完成) 
  → photo_view(查看照片) 
  → photo_save(保存)              ← 核心循环终点

延伸漏斗（可选）：share_click → share_success → share_backflow
```

### 6.6 埋点数据质量保障

1. **埋点验收**：每个版本上线前核对事件字典，使用测试环境全链路验证参数完整性；
2. **对账机制**：设备端计数器（如快门次数）与 App 事件交叉校验，差值超阈值自动告警；
3. **采样与限流**：低频事件全量采集，高频事件（如传输进度）按阈值抽样；
4. **一致性版本管理**：事件字典与代码同步维护，版本号标注，避免改版后口径漂移。

## 八、附录：名词与口径定义

| 名词 | 口径 |
|---|---|
| 设备 | 一台 AiKen 相机硬件（以序列号唯一标识） |

| 完成首冲 | 用户首次完成任意一卷冲扫 |
